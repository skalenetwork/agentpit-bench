## Gate (false-winner rate under daily peeking ≤ 5%)

- As written in the plan (P(δ>0) ≥ 0.95, expected loss < 0.02 sd, τ = 0.3): **5.9%** at 3.0 posts/day, worst case over the sensitivity runs **9.3%** → **FAIL**.
- P(δ>0) ≥ 0.975: worst case 3.9% → **PASS**.
- P(δ>0) ≥ 0.99: worst case 1.3% → **PASS**.

**Recommended for M5: P(δ>0) ≥ 0.975** (the lowest threshold that passes in every run), τ = 0.3, ε = 0.02, 45 days / 150 posts. Expected loss < ε never binds at these sample sizes (the ε = 0.01 row equals the ε = 0.02 row): P(δ>0) does all the work. The false-winner rate grows with traffic (more posts inside the 45 days means more chances to cross), so the gate is re-run whenever posts/day per slot changes a lot.

Definitions: *false winner* = the rule declares the challenger better at any daily check although δ = 0. *wrong among winners* = share of declared winners whose true δ ≤ 0 when δ is drawn from a fat-tailed prior (0.1·t₃: most effects tiny, a few large); most of those are near-zero effects on either side. *worse-arm traffic* = share of posts that went to an arm with a lower true mean.
